# 設計判断

|論点|比較|採用と理由|
|---|---|---|
|会話基盤|DM v4.2.0 / 自作DSL / 大きなStoryCore|DM固定版。編集・条件評価・コンパイラを活用し、代替エンジンを作らない|
|Godot|プリインストール4.6.3 / 公式4.7.2|希望に合わせ4.7.2。公式バイナリとチェックサム取得可能|
|分岐構造|枝ごとの全文 / 共通イベント＋条件文|後者。11イベントで合流し、重複と修正漏れを減らす|
|状態|Autoload多数 / Flow所有の1オブジェクト|後者。DMへ明示注入し、各テストを独立させる|
|UI|公式サンプル / 専用Control UI|専用UI。サンプル警告を持たず日本語の長文・スクロールと状態欄に集中|
|セーブ|なし / 行単位 / イベント境界1枠|境界1枠。小規模でも途中再開の価値があり、DM内部行IDの変更や副作用再適用を避けやすい|
|フォント|OS依存 / 同梱|OFL日本語フォントを固定取得して同梱。Linuxと将来のWebで文字化けを防ぐ|
|演出|音声・画像の先行実装 / signal窓口|signal窓口。接続先なしで常に進行し、不要な依存を増やさない|
|テスト|外部フレームワーク / Godot SceneTreeスクリプト|標準のみ。DMを直接呼ぶ実動テストで旧記法の静かな失敗を捕捉|
|乱数・戦闘・在庫|今回全部 / 将来の追加点のみ記録|後者。今回の検証対象は選択履歴と条件付き文章|

## 見送る機能
BGM、効果音、背景、立ち絵、ダイス、戦闘、汎用アイテムDB、複数セーブ枠、会話途中の厳密な復元、文章校正の完成、Web配信、複雑な人物設定。いずれも今回の完成条件に不要。

## 空リポジトリとPR
調査時点でmainを含む参照・コミットが存在しない。ローカルの開発ブランチで設計を先にコミットした。GitHub APIで空リポジトリにブランチを作るには初期コミットが必要なため、mainには案内READMEだけの初期コミットを作り、設計・ゲーム本体は開発ブランチへ保存する。mainへの成果の自動マージはしない。
