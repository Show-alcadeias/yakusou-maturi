# シナリオ設計（生成初稿・作者校正待ち）

## 正本の維持
2か月に1度の薬草祭り。採取の質と量を競う。錬金術師レオが効率を求めて自ら登山し遭難、家族が捜索願を出す。冒険者ムハンマドが何となく受ける。レオは鑑別・調合に優れ、登山の判断だけを誤った。主人公の背景・信条は固定しない。登場人物はこの2人が中心。

## イベントID
|ID|内容|主な分岐／遷移|
|---|---|---|
|prologue|祭りと依頼|approachへ|
|approach|登山口|捜索優先／採取優先を記録、exploreへ|
|explore|探索の共通拠点|未訪問3地点、常時可能な捜索、沢の調査後のみ近道|
|meadow|薬草の草地|採取（量3・品質1・遅れ2）／足跡（捜索+1）、exploreへ|
|stream|沢の跡|調査（目印を知る・捜索+1）／採取（量2・遅れ1）、exploreへ|
|ridge|岩場|調査（ロープ回収・捜索+1）／採取（量2・品質2・遅れ1）、exploreへ|
|discovery|レオ発見|優先方針、遅れ、目印ルートに応じた会話、aidへ|
|aid|救助手順|ロープは回収済み限定／レオの調合／ゆっくり支える|
|descent|帰路|薬草ありなら鑑別依頼（品質+1）／帰還を優先|
|appraisal|街での評価|採取なし／量不足／良質で十分な量を区別|
|ending|結末|救出速度×救助手順×薬草の成果を合成、タイトルへ|

3地点を回るとexplore表示前にdiscoveryへ。早期捜索も可能。全ルートで救出でき、薬草0も正規の結末。

## 状態変数と命名
`snake_case`。DMでは必ず `state.` / `flow.` を付ける。イベントIDと行動IDは英小文字、本文は日本語。状態の直接代入ではなく `state.act("行動ID")` に集約。

|変数|型・範囲|意味|
|---|---|---|
|priority|string: search/herbs/空|最初の方針|
|visited|Array[String]|探索済み地点（重複なし）|
|history|Array[String]|適用した行動ID（重複なし）|
|herbs|int 0..7|採取量|
|quality|int 0..4|品質点|
|delay|int 0..5|採取による捜索の遅れ（優先選択で最大1加算）|
|search_effort|int 0..4|捜索行動数|
|trail_known / rope_found|bool|調査の成果|
|shortcut_used|bool|条件付き近道を使った|
|rescued|bool|救助完了|
|aid_method|string: rope/alchemy/support/空|救助手順|

救出速度：delay <= 2なら早期、それ以外は日暮れ間際。薬草評価：herbs == 0で「手ぶらの救助者」、herbs >= 4かつquality >= 2で「救助と収穫」、それ以外は「小さな収穫」。速度と手順の文章は評価から独立して合成する。

## 編集規則と検証
- `story/story.dialogue` を文章の唯一の正本にする。共通の帰路・結末へ合流し、条件文で差分だけ挿入する。
- 条件付き応答は `- 文 [if state.flag /]`。旧 `[if state.flag]` を選択肢に使わない。
- 新しいイベントはGameFlowの許可ID・遷移・テストにも追加。新しい行動はGameStateの適用表と保存妥当性にも追加。
- 全応答をDM実行でたどり、到達性・結末・状態の不変条件を確認。真偽の対で近道、ロープ、再訪不可、鑑別依頼の可視性を検証する。
